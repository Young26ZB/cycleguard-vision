# Design

## Context

前三项变更提供跟踪主链路、方向和最近观测关联、虚拟观测回放。仓库 `KalmanFilterXYAH` 的默认观测噪声由预测框尺度构造。NSA 方案参照 [GIAOTracker](https://arxiv.org/abs/2202.11983) 与 [StrongSORT 的公式](https://arxiv.org/html/2202.13514)，以既有尺度噪声作为基准。

## Goals / Non-Goals

- **Goals** 在真实观测更新处引入置信度，形成能在固定质量约束下比较尾延迟的完整验证链路。
- **Non-Goals** 此方案只消费既有检测分数。分数模型训练、跨摄像头匹配、IPM 和违章判定各自独立验收。

## Decisions

1. **调整已有的观测噪声。** 在已匹配的真实检测更新时，用随分数下降而增大的有界比例缩放 `R_base`，并为每维保留正噪声下限。初始映射采用 `max(r_min, 1 - score)` 的缩放，其中 `r_min` 大于零且不超过 1。沿用线性方程求解和固定维度矩阵，避免显式求逆。若更新无效，退回一次普通更新并记录；仍无效时保留有限预测并按未取得有效更新处理，不提交损坏的状态。每个匹配最多提交一次真实更新。普通路径与虚拟噪声仍按各自配置。跟踪器接入扩展参数，已有其他调用使用默认噪声。
2. **先检查分数代理是否成立。** 在验证集按检测分数和遮挡程度分桶，记录与匹配真值框的定位误差、样本数及缺失情况。分数排序与定位质量关系弱时，保留普通噪声配置作对照并允许关闭 NSA。
3. **配对消融。** 固定第一部分权重和检测缓存，按视频序列划分验证和测试。验证集确定阈值、配置和质量门槛，测试前冻结。至少运行主链路、全开和逐项关闭配置，另比较固定方向权重和自适应方向权重。用 [HOTA 的 AssA](https://arxiv.org/abs/2009.07736)、IDF1 和 ID 切换衡量关联。遮挡事件按间隔分组，记录全部可判定重现、存在合格检测的重现、找回原 ID 和错误接上其他真值 ID。没有分母时标为不适用。
4. **按部署条件选择。** 用原始视频、固定模型和目标硬件复测，沿用主链路的跟踪核心与端到端边界。分别记录分位数、实际吞吐、持续积压、未处理帧、候选截断、ORU 回退和峰值内存。先筛选满足验证阶段登记的质量及实时性门槛的配置，再选择端到端 P95 最低者，同时保留 P99 供比较。只拿到缓存时，结论限定为跟踪核心对照。
5. **对照与主链路走同一入口。** 开关只改变对应模块，避免每个组合维护一条独立代码路径。基准输出与追踪日志按需开启。对照报告保留配置快照、数据和硬件标识，重复运行写入独立输出目录。

## Risks / Trade-offs

- 分数偏差可能加剧高分错框的状态漂移。用带正下限的保守映射并验证分数与定位误差，按配对消融决定是否启用。
- 跟踪缓存的高 FPS 可能掩盖解码、检测或写出瓶颈。分别测量核心和原始视频端到端，并记录掉帧与积压。
- 优先降低延迟可能降低拥堵场景中的召回。冻结质量门槛，并按负载、遮挡时长和截断原因分组复核结果。
- 视频或目标硬件尚未交付时无法验收实际性能。保留合成检查的记录，真实质量与实时性任务等待对应证据。

## Migration Plan

使用显式配置启用 NSA 和其他增强。只将通过联合验收的候选记录为实时配置。保留主链路及单项开关用于回退和比较。
