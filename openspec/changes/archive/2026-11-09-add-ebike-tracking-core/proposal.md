# Proposal

## Why

第二部分需要把第一部分的逐帧检测转成连续的带 ID 轨迹。目前仓库有检测接口和框架自带跟踪器，需要建立能独立运行、复现和测量时延的项目跟踪主链路。

## What Changes

- 定义逐帧检测和轨迹输出契约。提供检测缓存回放入口，以及使用原始视频与第一部分权重的推理入口，两者共用同一跟踪核心。
- 实现固定帧率单路视频的卡尔曼预测、IoU 一对一关联和轨迹生命周期。以确定性的合成回放作为首个验收场景。
- 建立可重跑的密集帧基准，记录跟踪核心与完整链路时延、输入负载和容量截断。
- 本变更是实施顺序第 1 项。观测中心关联、遮挡回放和噪声自适应分别由后续变更承担。IPM、ReID、显式转弯模型和跨摄像头身份留作独立研究。

## Capabilities

### New Capabilities

- `ebike-tracking-core`：逐帧输入输出、在线轨迹生命周期、关联容量与可复现时延基线。

### Modified Capabilities

## Impact

新增独立跟踪模块和视频/缓存入口，复用检测器的 `Results.boxes`、仓库卡尔曼实现及已有 NumPy/SciPy。真实回放需要逐帧框和分数，或原始视频与第一部分权重。
