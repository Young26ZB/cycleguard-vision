# Design

## Context

现有 `evaluate_model.py` 经 `model.val()` 输出常规验证指标。其 `--iou` 是后处理 NMS 阈值，常规精确率与召回率采用验证器的 F1 工作点。诊断规则需要固定的计分阈值、逐图资格和独立的忽略框。`train_ebike.py` 已支持外部数据 YAML 和 `--data-root`。现有数据加载器按图片文件名去扩展名匹配 YOLO 标签，并把缺标签解释为空目标。

## Goals / Non-Goals

**Goals**

- 将审核结论、YOLO 训练标签和诊断计分输入分开存放，建立从源图到结果的映射。
- 通过已有评估入口显式运行诊断计分，并能用固定预测验证全部边界行为。

**Non-Goals**

- 检测头、损失、训练器和原生后处理算法沿用现有实现。
- 现有 13 张图用于诊断。独立测试集、正式性能对比和违章检测属于后续研究工作。

## Decisions

### 1. 诊断复核清单与训练标签分离

采用版本化 JSON 诊断清单。以数据根下的完整相对图片路径（包含扩展名）作为唯一键，记录图片尺寸、来源摘要、复核状态、真实框、忽略框和待复核项。框用原图像素 `xyxy` 表示，满足 `0 ≤ x1 < x2 ≤ W`、`0 ≤ y1 < y2 ≤ H` 且所有值有限。输出训练标签时才转换为归一化 YOLO `class cx cy w h`，类别 `ebike` 对应 0。独立清单能够表达整图状态和忽略框，普通 YOLO 标签无法区分这些语义。

- 逐图状态为「已复核可计分」或「待复核」。前者显式记录真实框列表，即使为空。未建立记录或记录格式错误属于输入错误，不能默认为负样本。
- 待复核项记录实例的大致位置、原因、证据和结论。原因分为车型不确定、完整范围不确定、实例归属不确定。允许用可对应到同一实例的相邻帧辅助判断车型与归属，框坐标以当前帧可见线索为依据。缺失或损坏的标签记录单列为数据质量问题。
- 13 张图均需有复核记录。现有训练框只作复核底稿，不能直接作为诊断真值。所有未解除原因的图片列入待复核统计。
- 记录可判定的光照和逐目标遮挡状态。对已复核图从真实框计算目标数、最大两两 IoU 和框面积占原图面积的比例。真实框少于两个时最大两两 IoU 标为不适用。先保留原始统计，待样本分布可见后再确定高密度、高重叠和小目标的分组阈值。

### 2. 只读审计与显式发布派生数据

先在原数据上运行独立只读审计，直接读取图片与标签，输出相对路径、标签行号、异常类型和复核状态。采用独立审计是因为训练加载器允许缺标签，并可能生成缓存或修复损坏的 JPEG。审计时排除 `classes.txt`，检查图片标签配对、五列格式、有限值、类别、正宽高及框边界。训练集现有零宽框位于 `1129 (556).txt` 第 5 行。已发现的 177 个缺标签图片文件和 6 组同名多格式图片均需逐路径核对，重新扫描的结果优先于历史计数。

人工确认后才可应用处置清单。有效实例重画、误标行移除、真负样本写空标签、漏标补框。人在旁推行按背景处理，同时保留同图骑行目标。证据不足则保留待复核并阻止派生版本发布。原始集合和历史运行继续可用。

派生版本沿用训练和验证成员。将图片和已审阅的标签放入单独的 `images/<split>` 和 `labels/<split>` 结构，并为会映射到同一标签名的图片分配不同的派生文件名，保存一对一的来源映射与摘要。同名冲突处理只影响派生路径。发布前检查生成标签与加载器实际路径的对应关系。测试图仍由诊断清单从当前测试目录读取。使用新的数据 YAML 交给现有 `--data` 和 `--data-root`，可避免改变默认训练路径及既有复现实验。

### 3. 固定阈值和分级计分

建议在 `evaluate_model.py` 增加 `--diagnostic-manifest` 显式入口。该分支直接读取清单及可配置数据根，复用 YOLO 的单图预测结果和原图 `Boxes.xyxy`，保留置信度、类别以及各模型原生后处理。计分器接收逐图预测和审核数据，可独立接入合成预测。常规 `val/test` 分支及 `--iou` 的 NMS 语义保持原有行为。

- 独立的诊断配置以置信度 **0.25**、匹配 IoU **0.50**、忽略 IoA **0.80** 作为可覆盖的初始值。置信度采用固定通用起点，正式诊断对照前冻结并记录这三项，保持相同输入尺寸和候选数限制，记录各模型的原生后处理及适用的 NMS 阈值。若复用的预测入口执行严格大于的置信度过滤，推理预过滤取更低值，由计分器统一执行大于等于门槛。
- 只处理已复核可计分图片。对每张图按分数降序遍历达标的 `ebike` 预测，匹配 IoU 最大且达标的未匹配真实框。同分和同 IoU 按稳定索引处理。未匹配预测在所有主匹配完成后，依次判断已匹配骑行框的 IoU 门槛、单个忽略框的 IoA 门槛、普通误检。重复检出优先于忽略。未匹配的骑行真值计为漏检。
- `IoU = 交集面积 / 并集面积`，`IoA = 交集面积 / 预测框面积`。单个忽略框上的 IoA 适用于大小不同的预测和忽略区域。边界案例优先复核骑行目标与无人车相邻的情况。验证原图尺寸、路径、有限值与正面积，遇到非法输入给出具体记录，避免静默计分。
- 按全部计分图的计数汇总。精确率为 `TP / (TP + FP)`，召回率为 `TP / (TP + FN)`。重复比例为 `重复数 / (TP + FP)`，其中 FP 包含重复检出。定位偏差为已匹配框 `1 − IoU` 的中位数，附配对数。零分母或无定位配对用 JSON `null` 和文本「不适用」。记录图级明细、待复核原因、阈值、输入尺寸、候选数限制、权重标识、数据版本与已知训练重叠。没有可计分图片时仍报告覆盖与原因。

## Risks / Trade-offs

- 忽略框过宽可能吞掉无关误检。使用单框 IoA、优先识别重复，并保留触发忽略的区域和 IoA 供抽查。
- 13 张图与训练集重叠且包含相邻画面。报告明确标为诊断，解释样本覆盖，禁止用此结果选择阈值或支持泛化结论。
- 派生数据需要额外磁盘空间。优先使用可独立迁移的图片副本与来源映射，并在新目录完成全部校验后才发布 YAML。

## Migration Plan

先生成只读审计与 13 张图的复核清单，再经人工核对生成独立派生版本。使用新配置验证数据可读性后，在新运行目录启用诊断模式。需要回退时，继续使用原数据 YAML 和常规评估命令。真实数据训练与 CUDA 验证保留为阿里云任务。
